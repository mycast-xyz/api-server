# user-bot 배포 준비 점검 — 2026-11-25

**현재 코드의 Git 푸시 + 기존 Jenkins 빌드만으로는 기능 반영이 완료되지 않습니다.** 코드 컴파일·재시작 외에 DB 변경과 토큰 암호화 키 준비가 빠져 있습니다. 이번 점검에서 운영 파일·DB·Jenkins 설정을 수정하거나 빌드를 시작하지 않았습니다.

## 운영에서 확인한 사항

| 항목 | 현재 상태 |
|---|---|
| DB | MySQL 5.6.33, 기존 user 테이블 InnoDB |
| user-bot 테이블 | user_bot, user_bot_token 모두 없음 |
| API DB 계정 | 대상 DB 테이블 생성에 필요한 권한 있음 |
| 기존 API Jenkins | npm install → npm run build → pm2 reload api (또는 기존 시작 명령) |
| API postbuild | 영상 준비·검사 및 실행 환경 확인만 수행. user-bot SQL/키 준비 호출 없음 |
| 채팅 Jenkins | npm install → npm run build → pm2 reload main-chat (또는 기존 시작 명령) |
| 암호화 키 | API .env 및 Jenkins 설정에 USER_BOT_TOKEN_KEY 없음 |

명령·환경의 **키 이름과 준비 여부만** 확인했습니다. 비밀번호·토큰·실사용자 데이터는 보고서에 수집하지 않았습니다. PM2 실행 환경은 읽기 권한으로 확인하지 못했으므로 해당 환경까지 검증 완료로 취급하지 않습니다.

## 필요한 추가 작업

1. **새 테이블 생성**: 별도 `vega-user-bot-prepare` 작업이 DB 백업 후 `migrations/20261125-user-bots.sql`을 적용하고 결과 스키마를 확인합니다. 기존 user·채팅·기존 봇 테이블을 바꾸지 않습니다. MySQL DDL의 중간 실패·재시작을 고려해 부분 생성 상태를 검사합니다.
2. **고정 암호화 키 보관/로딩**: 전용 작업이 `/var/lib/jenkins/mycast-data/user-bot/token.key`에 최초 한 번 키를 저장합니다. API 소스가 이 파일을 직접 읽도록 했으며 기존 .env·postbuild·PM2 명령을 바꾸지 않습니다. 운영 API 프로세스 UID 0, Jenkins 폴더 소유 UID 123을 읽기 전용으로 확인했으므로 현재 구성에서 0600 키를 API가 읽을 수 있습니다.
3. **실패 시 중단**: 전용 준비 작업은 실패하면 중단하고 다른 작업을 호출하지 않습니다. 기존 빌드 작업을 자동으로 차단하도록 수정하지는 않으므로 운영자는 준비 성공 후 기존 작업을 실행해야 합니다. 순서는 전용 준비(백업/DB/키) → API/채팅 → 웹 → Windows입니다.

사용자 결정에 따라 기존 Jenkins 구성은 변경하지 않고 **전용 작업 정의와 스크립트를 별도로 준비했습니다**. 등록·실행 방법은 [전용 작업 안내](../jenkins/USER-BOT-PREPARE.ko.md)를 참고하세요. 현재 로컬 검증 34개를 통과했으며 Jenkins 실제 등록·운영 실행은 하지 않았습니다. 전용 작업으로 준비를 완료하면 매번 SQL을 따로 입력할 필요가 없습니다.

## 확인된 호환성과 남은 범위

운영과 같은 MySQL 5.6.33을 별도 로컬 포트에 실행해 새 SQL 및 실제 Redis/로그인/C# 봇을 포함한 24개 검사를 통과했습니다. 기존 API 13개·채팅 단위 검사 8개도 통과했습니다. 운영 DB에 실제 쓰기, Linux/PM2에서 새 코드 실행, 공개 TLS/프록시 및 클라이언트 배포 후 화면 확인은 수행하지 않았습니다.

비공개 채팅 저장소는 배포된 Git 이력에서 로컬로 가져온 상태입니다. 실제 배포 전에 원격 쓰기 권한과 Jenkins가 읽는 저장소·브랜치에 커밋이 도달하는지도 확인해야 합니다. 현재 feature/user-bot은 로컬 작업이며 운영 main에는 반영하지 않았습니다.
